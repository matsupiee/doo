# 他の人のやりたいことに参加する

> ステータス: スキーマ済み / API・UI は後続

## ストーリー

ユーザーとして、
他の人が登録した「やりたいこと」を見て自分も一緒にやりたい。
そうすれば、達成したときに一緒にやった人と共同の達成として記録できる。

## 受け入れ条件

- 登録されたやりたいことはサインインしている全ユーザーに見える。非公開のものは無い。
- 他の人のやりたいことに自分から参加できる。承認も招待も要らず、その場で参加者になる。
- 作成者は登録時点で参加者になっているので、参加者一覧には必ず作成者が並ぶ。
- 同じやりたいことに同じ人が二重に並ばない（何度参加しても参加者は増えない）。
- やりたいことの詳細に、いま参加している人の一覧が出る。
- ミッションから抜けられる。ただし、自分がそのミッションで達成を1件でも記録していると
  抜けられない。抜けると自分の過去の達成記録が道連れで消えるため、API がエラーを返す。
- 判定の対象は自分の達成だけ。他の参加者がそのミッションを達成していても、自分が
  達成していなければ抜けられる。抜けたあとも他の人の達成記録はそのまま残る。
- 自分の達成が0件の参加者は抜けられ、参加者一覧から消える。
- 作成者は自分のやりたいことから抜けられない（API がエラーを返す）。
  やめるときはやりたいことごと消す。
- 自分のやりたいことに誰かが参加すると、作成者に通知が届く
  → [通知で気づく](./notifications.md)
- 共同達成に含められたとき、まだ参加者でなければその場で参加者になる
  → [達成を記録して投稿する](./record-completion.md)

## データの持ち方

- 参加は `mission_participant` に1行作ること、退出はその行を消すことと同じ。
  状態カラム（承認待ちなど）も `left_at` による論理削除も持たない。
- 複合主キー `(mission_id, user_id)` が二重の参加を DB レベルで弾く。
- `mission_completion_participant` から `mission_participant` への FK は cascade なので、
  退出はその人自身の達成参加の記録を消してしまう。だから自分の達成がある参加者の
  退出は API で禁止する。消えるのは退出する本人の行だけで、同じ達成に並んでいる
  他の参加者の行は残る。

## 動作確認の手順

（API・UI は後続。現時点ではスキーマのみ）

1. `bun run db:seed` でシードを流す。
2. 他のユーザーのやりたいことを開いて参加し、参加者に自分が並ぶ。
3. もう一度参加しても参加者が増えない。
4. 作成者の通知一覧に「参加されました」が届いている。
5. 達成のないミッションから抜けると、参加者一覧から自分が消える。
6. 達成のあるミッションから抜けようとするとエラーになる。
7. 作成者が自分のやりたいことから抜けようとするとエラーになる。
