# やりたいことを登録する

> ステータス: スキーマ済み / API・UI は後続

## ストーリー

**ユーザー** として、**自分のやりたいことを登録しておきたい**。

そうすれば、**思いついたときに書き留めて、あとから達成を記録できる**し、**同じことをやりたい人が見つけて一緒にやれる**。

## 受け入れ条件

- 作成画面で **タイトル** を入れるだけで登録できる。説明（`description`）は任意。
- 登録したやりたいことの作成者は自分（`mission.creator_id`）になる。
- **作成者は同時に参加者になる**（`mission_participant` に自分の行ができる）。
  だから参加者0人のやりたいことは存在しないし、登録した本人はそのまま達成を記録できる。
- 登録したやりたいことは **サインインしている全ユーザーに見える**。非公開にはできない。
- タグは任意で複数付けられる → [やりたいことにタグをつける](./mission-tags.md)
- 登録した時点では **達成は0件**。達成の記録は
  [達成を記録する](./record-completion.md) の導線から行う。
- プロフィールの「やりたいこと」に、自分が作ったものが新しい順に並ぶ。
- 他の人のやりたいことは一覧から見えて、そこから参加できる
  → [他の人のやりたいことに参加する](./participate-in-mission.md)

## データの持ち方

| 表                    | 役割                                                       |
| --------------------- | ---------------------------------------------------------- |
| `mission`             | やりたいこと本体（`title` / `description` / `creator_id`） |
| `mission_tag`         | 付けたタグ（自由入力、`(mission_id, title)` で一意）       |
| `mission_participant` | そのやりたいことを「やる」人。作成者の行もここに入る       |

`mission` の作成と作成者の `mission_participant` は同じトランザクションで作る。
`creator_id` は「誰が言い出したか」として残す（参加者一覧からは作成者を判別できない）。
公開範囲の列は持たない。全体公開が既定で、限定公開の要件が出てから足す。

## 動作確認の手順

（API・UI は後続。現時点ではスキーマのみ）

1. `bun run db:seed` でシードを流す。
2. 作成タブでタイトルだけ入れて登録する。
3. プロフィールの「やりたいこと」に、いま登録したものが並ぶ。
4. その詳細を開くと、参加者に自分だけが並んでいる。
5. 達成が0件なので、達成一覧には何も出ない。
6. 別のユーザーでサインインしてそのユーザーのプロフィールを見ても、やりたいこと一覧から見える。そして、参加できる。
