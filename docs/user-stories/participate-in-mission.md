# 他の人のやりたいことに参加する

> ステータス: 実装済み。通知だけ後続（[通知で気づく](./notifications.md)）

## ストーリー

ユーザーとして、
他の人が登録した「やりたいこと」を見て自分も一緒にやりたい。
そうすれば、達成したときに一緒にやった人と共同の達成として記録できる。

## 動作確認の手順

1. `bun run db:seed` でシードを流す。
2. サインインした状態で、他のユーザーが登録した「やりたいこと」を開く。
   - 登録された「やりたいこと」は、サインインしている全ユーザーから見える。
   - 非公開の「やりたいこと」は存在しない。
   - 詳細画面に現在の参加者一覧が表示される。
   - 作成者は登録時点で参加者になっているため、参加者一覧に必ず表示される。
3. 他のユーザーの「やりたいこと」に参加する。
   - 承認や招待は不要で、その場で参加できる。
   - 参加後、参加者一覧に自分が表示される。
   - 作成者に「参加されました」という通知が届く。
   - → [通知で気づく](./notifications.md)
4. 同じ「やりたいこと」にもう一度参加する。
   - 同じユーザーが二重に参加者として登録されない。
   - 何度参加処理を実行しても、参加者数は増えない。
5. 自分がまだ達成を記録していない「やりたいこと」から抜ける。
   - 正常に退出できる。
   - 退出後、参加者一覧から自分が消える。
   - 他の参加者や、その人たちの達成記録には影響しない。
6. 自分がその「やりたいこと」で達成を1件以上記録した状態で抜ける。
   - API がエラーを返し、退出できない。
   - 判定対象は自分自身の達成だけ。
   - 他の参加者が達成していても、自分が達成していなければ退出できる。
7. 作成者が自分で作成した「やりたいこと」から抜ける。
   - API がエラーを返し、退出できない。
   - 作成者がやめたい場合は、「やりたいこと」自体を削除する。
8. 共同達成に、まだその「やりたいこと」に参加していないユーザーを含める。
   - 共同達成への追加と同時に、そのユーザーも参加者になる。
   - 参加者一覧にも表示される。
   - → [達成を記録して投稿する](./record-completion.md)

## データの持ち方

- 参加状態は `mission_participant` で管理する。
  - 参加すると `(mission_id, user_id)` の行を1件作成する。
  - 退出すると、その行を削除する。
  - 承認待ちなどの状態カラムは持たない。
  - `left_at` などによる論理削除も行わない。
- `mission_participant` は `(mission_id, user_id)` を複合主キーにする。
  - 同じ「やりたいこと」に同じユーザーが複数回参加することを DB レベルで防ぐ。
- 作成者も `mission_participant` に登録する。
  - 「作成者」と「参加者」はデータ上は別の概念だが、作成時に必ず参加者としても登録する。
- `mission_completion_participant` は `mission_participant` を参照する。
  - 退出によって `mission_participant` の行を削除すると、そのユーザーに紐づく達成参加の行も
    cascade で削除される。
  - 過去の達成記録を失わないため、自分自身の達成が1件でもある場合は API で退出を禁止する。
  - 削除される可能性があるのは退出する本人の達成参加行だけで、同じ達成に参加している
    他ユーザーの行には影響しない。
- 共同達成に未参加ユーザーを追加する場合は、先に `mission_participant` を作成してから
  達成参加者として登録する。
