# 相手のいないミッションを作れるようにする

- 日付: 2026-09-04
- ステータス: 採用

## 背景

これまで `mission.create` は「自分に渡す」か「誰かに渡す」のどちらかを必須にしていた
（zod の `refine`）。思いついたミッションを、渡す相手を決めずに書き留めておきたいという要望が出た。

## 決定

`mission.create` の必須条件を **リレーのときだけ** に緩める。リレーは最初に走る人がいないと
チェーン自体が始まらないため、そこは従来どおり必須のまま残す。

あわせて `mission.assign` を追加し、既存のミッションをあとから渡せるようにした。
作成者のみ実行でき、すでに持っている人はスキップし、リレーのミッションは対象外（リレーは
クリアした人がバトンを渡す仕組みなので、作成者が横から足すと depth / parent の整合が崩れる）。

## 理由

- 相手なしで作れるだけだと、そのミッションを渡す手段が無く行き止まりになる。
  `assign` をセットにして初めて機能として成立する。
- リレーの制約を残すのは、`relay` 行が作られたのに参加者0人という状態を作らないため。

## 却下した選択肢

- **`refine` を完全に外す**: 相手のいないリレーが作れてしまい、`/relay/[relayId]` が空のツリーになる。
- **`assign` を作らず、UI で「同じ内容で作り直す」**: mission が重複し、カテゴリや達成履歴が分散する。

## 影響

- `mission.create` の `assignmentCount` が 0 になりうる。呼び出し側（トーストの文言）を調整した。
- `mission.sent` は assignment が0件のミッションも返す（従来から LEFT JOIN なので挙動は同じだが、
  `total` / `cleared` を数値に正規化した）。
