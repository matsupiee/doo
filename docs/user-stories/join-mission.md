# 他の人のやりたいことに join する

> ステータス: スキーマ済み / API・UI は後続

## ストーリー

**ユーザー** として、
他の人が登録した「やりたいこと」を見て **自分も一緒にやりたい**。
そうすれば、**達成したときに一緒にやった人と共同の達成として記録できる**。

## 受け入れ条件

- 他の人のやりたいことに **自分から join できる**。承認も招待も要らず、その場で参加者になる。
- 同じやりたいことに **同じ人が二重に並ばない**（何度 join しても参加者は増えない）。
- やりたいことの詳細に、いま参加している人の一覧が出る。
- ミッションから **抜けられる**。ただし **達成が1件でもある場合は抜けられない**
  （抜けると過去の達成記録が道連れで消えてしまうため、API がエラーを返す）。
- 達成が0件の参加者は抜けられ、参加者一覧から消える。

## データの持ち方

- join は `mission_participant` に1行作ること、退出はその行を消すことと同じ。
  状態カラム（承認待ちなど）も `left_at` による論理削除も持たない。
- 複合主キー `(mission_id, user_id)` が二重 join を DB レベルで弾く。
- `mission_completion_participant` から `mission_participant` への FK は cascade なので、
  退出は達成の記録を消してしまう。だから **達成のある参加者の退出は API で禁止する**。

## 未決

- 参加していない人を共同達成に含めたいとき（その場で誘われた人など）、記録時に暗黙に
  join させるか、先に join を求めるか。
- やりたいことの公開範囲。join できる以上、未達成のやりたいことが他人に見える。
- 自分のやりたいことに誰かが join したことに気づく通知が無い。

## 動作確認の手順

（API・UI は後続。現時点ではスキーマのみ）

1. `bun run db:seed` でシードを流す。
2. 他のユーザーのやりたいことを開いて join し、参加者に自分が並ぶ。
3. もう一度 join しても参加者が増えない。
4. 達成のないミッションから抜けると、参加者一覧から自分が消える。
5. 達成のあるミッションから抜けようとするとエラーになる。
