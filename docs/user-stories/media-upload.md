# 達成の証拠として写真・動画をアップロードする

> ステータス: `packages/storage` / `upload` ルーターは実装済み。
> 投稿側の画面は新しいコンセプトに合わせて後続で作り直す。

## ストーリー

やりたいことの達成・進捗を投稿するユーザーとして、
手元の写真や動画をそのままアプリから投稿したい。
そうすれば、どこかに画像をアップして URL を取ってくる手間なしに、達成を残せる。

## 背景

以前は「写真のURL」テキスト欄に外部の URL を貼るしかなく、実質的に投稿できない状態だった。
実体は Cloudflare R2 に置き、投稿（`post.media_url`）には公開 URL だけを保存する。

## 動作確認の手順

1. `bun run db:seed` でシードを流す。
2. 参加している「やりたいこと」を開き、「達成を記録する」で写真を選ぶ。
   - 「ライブラリから選ぶ」か「撮影する」を選べる。
   - 初回はフォトライブラリ／カメラの許可を求められ、許可すると選択画面が開く。
   - 許可していないと「写真へのアクセスが許可されていません」と出る。
3. 写真を選ぶ。
   - サムネイルが出て「写真をアップロード中…」が表示される。
   - 完了すると「写真をアップロードしました」に変わる。
   - アップロードが完了するまで、投稿ボタンは押せない。
4. 「達成として投稿する」を押す。
   - ホームのフィードにその写真が並ぶ。
   - 達成そのものの記録は別のストーリーで扱う。
   - → [達成を記録して投稿する](./record-completion.md)
5. 動画を選んで、同じ流れで投稿する。
   - ライブラリは動画だけを、カメラは録画モードで開く。
   - アップロード後はフィードに動画の URL が出る（プレイヤーは未実装）。
6. 写真から動画へ、種類を切り替える。
   - 前の種類でアップロードしたファイルは破棄される。
   - もう一度選び直す必要がある。
7. 達成せずに、進捗報告として写真を添えて投稿する。
   - 同じ流れで添えられる。アップロードの導線は達成報告と共通。
   - 違いは達成（`mission_completion`）を作るかどうかだけ。
8. 上限を超えたファイルや、許可していない形式を選ぶ。
   - 失敗した理由が表示される。

   | 状況                                 | 表示                                                             |
   | ------------------------------------ | ---------------------------------------------------------------- |
   | 写真が 10MB を超えている             | 「ファイルが大きすぎます（最大 10MB）」                          |
   | 動画が 100MB を超えている            | 「ファイルが大きすぎます（最大 100MB）」                         |
   | 許可していない形式（PDF など）       | 「Unsupported content type. …」                                  |
   | フォトライブラリ／カメラの許可がない | 「写真へのアクセスが許可されていません」                         |
   | サーバーに R2 が未設定               | 「アップロード先が未設定です。サーバーの R2 設定を確認してください」 |
   | R2 への PUT が失敗                   | 「アップロードに失敗しました (ステータスコード)」                |

## データの持ち方

- アップロードした実体は Cloudflare R2 に置く。DB には公開 URL だけを保存する。
  - `post.media_type` に `photo` / `video` / `text` を持つ。
  - `post.media_url` に公開 URL を持つ。テキストだけの投稿では `null`。
- presigned URL は `upload.createUploadUrl` が発行する。
  - サインインしていないと発行されない（`UNAUTHORIZED`）。
  - オブジェクトキーはサーバーがセッションのユーザー ID から組み立てる。
    クライアントは自分のキーを指定できないので、他人の領域に上書きできない。
  - キーには cuid2 が入るので、公開バケットでも他人の投稿を推測してたどれない。
  - 有効期限は 5 分。
  - `Content-Type` は署名に含まれるので、許可した形式と違うものは R2 側で弾かれる。
