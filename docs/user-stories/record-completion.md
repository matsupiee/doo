# 達成を記録して投稿する（個人・共同）

> ステータス: 実装済み。通知だけ後続（[通知で気づく](./notifications.md)）

## ストーリー

やりたいことの参加者として、達成したことを、一緒にやった人と一緒に記録したい。
そうすれば、個人の達成も共同の達成も、同じ形でフィードとプロフィールに残る。

## 動作確認の手順

1. `bun run db:seed` でシードを流す。
2. 参加している「やりたいこと」を開き、自分ひとりで達成を記録する。
   - 達成を記録すると、必ず投稿が1件作られる。投稿のない達成は存在しない。
   - 達成参加者が1人だけなので、個人達成として記録される。
   - 自分のプロフィールの達成一覧にだけ並ぶ。
   - 証拠の写真・動画は投稿に添えられる。
   - → [達成の証拠として写真・動画をアップロードする](./media-upload.md)
3. 一緒に達成した人を1人以上選んで、達成を記録する。
   - 達成参加者が複数人なので、共同達成として記録される。
   - フィードに投稿が1件出る。人数ぶんの投稿にはならない。
   - 参加した全員のプロフィールに、同じ達成が並ぶ。
   - 個人達成と共同達成でテーブルもフラグも分けない。違いは達成参加者の行数だけ。
4. 同じ人を、同じ達成の一緒に達成した人に二重に指定する。
   - 二重には登録されない。
5. まだその「やりたいこと」に参加していない人を、一緒に達成した人に指定する。
   - その人がその場で参加者になり、達成参加者としても登録される。
   - 参加者一覧にもその人が並ぶ。
   - その人に通知が届く。もとから参加者だった人も、通知は同じように受け取る。
   - → [通知で気づく](./notifications.md)
6. 達成日時に先週の日付を指定して記録する。
   - 記録した日時とは別に、達成日時を指定できる。
   - 指定した日付で表示される。
   - 未指定なら記録時刻を使う。
7. 同じ「やりたいこと」をもう一度達成として記録する。
   - 何度でも記録できる。達成一覧に2件並ぶ。
   - 達成は状態ではなくイベントとして扱う。「毎朝走る」のような繰り返しのため。
8. 達成せずに、進捗報告として投稿する。
   - フィードには出るが、達成一覧には並ばない。
   - 投稿に達成はぶら下がらない。

## データの持ち方

- 達成イベントは `mission_completion` に1行作る。
  - `mission_id` / `post_id` / `completed_at` を持つ。
  - `completed_at` は記録時刻とは別の値を入れられる。
  - 同じミッションに対して何行でも作れる。`(mission_id, user_id)` の一意制約は張らない。
- `mission_completion.post_id` は `NOT NULL` かつ unique にする。
  - 「達成には必ず投稿」「1投稿は最大1達成」を DB が保証する。
  - 投稿が消えたら達成も消えるよう cascade にする。
- 誰が達成したかは `mission_completion_participant` が持つ。
  - `(completion_id, user_id)` を複合主キーにして、同じ達成への二重参加を防ぐ。
  - 行が1件なら個人達成、複数件なら共同達成。
  - プロフィールの達成一覧のために `user_id` に索引を張る。
- 達成参加者は、そのミッションの参加者でなければならない。
  - `mission_completion_participant` に `mission_id` を持たせ、複合 FK を2本張って担保する。
  - `(completion_id, mission_id)` は `mission_completion (id, mission_id)` を参照する。
  - `(mission_id, user_id)` は `mission_participant (mission_id, user_id)` を参照する。
- 未参加の人を共同達成に含めるときは、先に `mission_participant` を作る。
  - 達成の記録と同じトランザクションで作る。
  - 制約を緩めるのではなく、制約を満たす行を先に作る操作。DB 側の担保はそのまま効く。
- 投稿は `post` に作る。達成報告にも進捗報告にも同じ表を使う。
  - 達成のない `post` が進捗報告にあたる。
