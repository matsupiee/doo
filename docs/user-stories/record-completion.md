# 達成を記録して投稿する（個人・共同）

> ステータス: スキーマ済み / API・UI は後続

## ストーリー

**やりたいことの参加者** として、
**達成したことを、一緒にやった人と一緒に記録したい**。
そうすれば、**個人の達成も共同の達成も、同じ形でフィードとプロフィールに残る**。

## 受け入れ条件

- 参加しているやりたいことについて、達成を記録できる。
- 達成を記録すると **必ず投稿が1件作られる**。投稿のない達成は存在しない。
- 1つの投稿が2つの達成を指すことはない。
- 達成には **一緒に達成した人を複数人ぶら下げられる**。
  - 1人だけなら **個人達成**、複数人なら **共同達成**。テーブルもフラグも分けない。
  - 同じ人を同じ達成に二重には入れられない。
  - **達成に入れられるのは、そのやりたいことの参加者だけ**。参加していない人を指定すると
    エラーになる（DB の複合 FK でも弾かれる）。
- **達成日時は、記録した日時とは別に指定できる**（あとから「先週やった」を登録できる）。
  未指定なら記録時刻を使う。
- 同じやりたいことを **何度でも達成として記録できる**（「毎朝走る」のような繰り返しのため）。
  達成は状態ではなくイベントとして扱う。
- **達成していなくても、進捗報告として投稿できる**。その投稿には達成がぶら下がらない。
- 証拠の写真・動画は投稿に添える → [達成の証拠として写真・動画をアップロードする](./media-upload.md)
- プロフィールから、その人が達成したこと（個人・共同の両方）を一覧できる。
  共同達成は、参加した全員のプロフィールに同じ達成として並ぶ。
- ホームのフィードには、達成報告の投稿も進捗報告の投稿も並ぶ。

## データの持ち方

| 表                               | 役割                                             |
| -------------------------------- | ------------------------------------------------ |
| `mission_completion`             | 達成イベント1件。`mission_id` / `post_id` / `completed_at` |
| `mission_completion_participant` | その達成を誰が達成したか。`(completion_id, user_id)` が主キー |
| `post`                           | フィード投稿。達成報告にも進捗報告にも使う                    |

- `mission_completion.post_id` は `NOT NULL` かつ unique。
  「達成には必ず投稿」「1投稿=最大1達成」を DB が保証する。
- `mission_completion` に `(mission_id, user_id)` のような一意制約は張らない。
  同じミッションの複数回達成が許される。
- `mission_completion_participant` は `mission_id` を持ち、複合 FK を2本張ることで
  「達成が属するミッション」と「その人が参加しているミッション」を同じ値に固定する。

## 動作確認の手順

（API・UI は後続。現時点ではスキーマのみ）

1. `bun run db:seed` でシードを流す。
2. 参加しているやりたいことを開き、達成を記録する。一緒に達成した人を1人選ぶ。
3. フィードに投稿が1件出て、両方のプロフィールの達成一覧に同じ達成が並ぶ。
4. 1人だけで記録した場合は、個人達成として自分のプロフィールにだけ並ぶ。
5. 同じやりたいことをもう一度達成として記録できる。達成一覧に2件並ぶ。
6. 達成日時に先週の日付を指定して記録すると、その日付で表示される。
7. 参加していない人を一緒に達成した人に指定するとエラーになる。
8. 達成せずに進捗報告として投稿すると、フィードには出るが達成一覧には並ばない。
