# やりたいことを登録する

> ステータス: スキーマ済み / API・UI は後続

## ストーリー

ユーザーとして、自分のやりたいことを登録しておきたい。

そうすれば、思いついたときに書き留めて、あとから達成を記録できるし、同じことをやりたい人が見つけて一緒にやれる。

## 動作確認の手順

1. `bun run db:seed` でシードを流す。
2. 作成タブでタイトルだけ入れて登録する。
   - タイトルだけで登録できる。説明（`description`）は任意。
   - 登録した「やりたいこと」の作成者は自分になる。
   - タグは任意で、1つも付けずに登録できる。
   - → [やりたいことにタグをつける](./mission-tags.md)
3. プロフィールの「やりたいこと」を開く。
   - 自分が作ったものが新しい順に並ぶ。
   - いま登録したものが先頭に並ぶ。
4. 登録した「やりたいこと」の詳細を開く。
   - 参加者一覧に自分だけが並んでいる。作成と同時に自分が参加者になっている。
   - 達成は0件なので、達成一覧には何も出ない。
   - 達成の記録はこの画面から行う。
   - → [達成を記録して投稿する](./record-completion.md)
5. 別のユーザーでサインインして、そのユーザーのプロフィールを見る。
   - 登録した「やりたいこと」が一覧から見える。非公開にはできない。
   - そこから参加できる。
   - → [他の人のやりたいことに参加する](./participate-in-mission.md)

## データの持ち方

- 「やりたいこと」本体は `mission` に1行作る。
  - `title` は必須で、`description` は任意。
  - 作成者は `creator_id` に持つ。
  - 公開範囲の列は持たない。全体公開が既定で、限定公開の要件が出てから足す。
- `mission` の作成と同時に、作成者の `mission_participant` を作る。
  - 同じトランザクションで作るので、参加者0人の「やりたいこと」は存在しない。
  - 作成者が参加者でないと自分の達成すら記録できないため、必ず作る。
- `creator_id` は参加者とは別に残す。
  - 「誰が言い出したか」の情報であり、`mission_participant` からは判別できない。
- タグは `mission_tag` に1タグ1行で持つ。
  - → [やりたいことにタグをつける](./mission-tags.md)
